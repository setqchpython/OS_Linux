# Пересмотр доступа · ops-03

Сверено с ПД-02. Команды проверки: `getent group sudo devops finance`, `ls -l /etc/sudoers.d`, `sudo -l -U ИМЯ`, `ls -ld /srv/devops /srv/finance /srv/share`. Факт по группам до работ такой: `kozlov` в `devops`, `finance` и `sudo`; `orlova` только в `devops`; `lebedeva` только в `finance`.

## Группа sudo

В `sudo` входит увольняемый администратор, и отдельно ему выдано личное правило без пароля на все команды. Для инженера эксплуатации группа `sudo` допустима, пока он работает. Правило `NOPASSWD: ALL` на конкретного человека политика запрещает.

После заявки `kozlov` в `sudo` не состоит, файла `/etc/sudoers.d/90-kozlov` нет.

`orlova` принимает выкладку, но в группу `sudo` её не добавляли. Для `deploy.sh` и ключа ей хватает владельца каталога и группы `devops`. Предложение: не включать её в `sudo` «на всякий случай». Если понадобится администрирование, завести отдельный файл в `/etc/sudoers.d` на конкретные команды, режим `440`, правка через `visudo`.

`lebedeva` в `sudo` не входит. Так и должно быть: бухгалтеру не нужны права root.

## Каталоги /srv

| Каталог | Как должно быть по роли | Что сделать |
|---|---|---|
| `/srv/devops` | ответственный за выкладку, группа `devops` | уже передано `orlova:devops`, ключ режим `600` |
| `/srv/finance` | бухгалтер, группа `finance` | не трогать, `lebedeva` читает документы |
| `/srv/share` | обмен файлами | каталог открыт всем на запись. Предложение: заменить общий режим `1777` на каталог группы обмена и не класть туда дампы и ключи. В этой заявке дамп из каталога уже убран, режим каталога оставлен, чтобы не менять чужую работу без отдельной заявки |

Личных правил sudo у остальных пользователей стенда нет.
