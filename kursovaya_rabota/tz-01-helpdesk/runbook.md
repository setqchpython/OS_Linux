## Первый отказ запуска

Команда `sudo bash tools/show-start-failure.sh` копирует поставку как есть и запускает службу от `helpdesk`.

Ожидаемая причина, её должна напечатать сама служба: секреты поставки имеют режим `644`, последняя цифра не 0, и `helpdesk-api` отказывается стартовать. Текст с экрана вставьте сюда:

```
Режим секретов в поставке: 644
Запуск от helpdesk без смены прав:
helpdesk-api failed to start:
2026-11-09 03:15:27 level=error /etc/helpdesk/secrets.env is accessible by other users (644), refusing to start
```

Права при этом не ослаблялись. В рабочем скрипте секрет ставится в режим `400`: читать может только владелец `helpdesk`, для остальных доступ закрыт, и проверка режима в службе проходит.

Вторая причина, если секрет уже закрыт, а процесс 2.3 ещё жив: служба считает, что адрес занят, потому что ищет любой процесс со строкой `bin/helpdesk-api`. Поэтому 2.3 останавливается до старта 2.4.1. Каталог 2.3 не удаляется.

## Что пошло не так и как исправили

- Поставка кладёт `secrets.env` с доступом остальных. Исправление — режим `400`, владелец `helpdesk`. Это сужение прав, не расширение.
- `UMASK=0002` не проходит проверку маски. В конфиге стоит `0027`: у новых файлов нет записи для группы и нет доступа для остальных.
- Пока жив процесс 2.3, 2.4.1 не стартует. Процесс 2.3 завершается, файлы 2.3 остаются.
- Если пробный запуск уже создал `api.log` с широким режимом, `provision.sh` удаляет этот файл и создаёт журнал заново с группой `helpdesk-readers` и режимом `640`.
