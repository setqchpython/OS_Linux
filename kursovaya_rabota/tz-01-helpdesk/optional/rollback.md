# План возврата к helpdesk 2.3

План на случай, если 2.4.1 не поднимется в окне 06:00–08:00.
Возврат по этому файлу не выполнялся: заявка CHG-2026-1047 откат не планирует.
Команды ниже — для копии сервера. На рабочем helpdesk-01 путь версии 2.3
берётся из паспорта (`pgrep -af helpdesk`), а не из памяти.

Версия 2.3 — цикл `sleep` из домашнего каталога прежнего инженера.
Она не слушает порт. Признак работы — процесс, а не ответ HTTP.

## 1. Зафиксировать, что 2.4.1 не работает

```bash
sudo -u helpdesk /usr/local/bin/helpdesk-ctl status
sudo tail -n 20 /var/log/helpdesk/api.log
pgrep -af helpdesk
```

Дальше идти только если служба не держит pid или в журнале повторяется отказ.
Файлы 2.4.1 не удалять: после окна их можно запустить снова.

## 2. Остановить 2.4.1

```bash
sudo -u helpdesk /usr/local/bin/helpdesk-ctl stop
```

Если pid-файла уже нет:

```bash
sudo pkill -KILL -f '/usr/local/bin/helpdesk-api' || true
```

Проверка: процесса 2.4.1 нет, каталоги `/etc/helpdesk` и `/var/lib/helpdesk` на месте.

```bash
pgrep -af '/usr/local/bin/helpdesk-api' || echo "2.4.1 остановлена"
```

## 3. Вернуть процесс 2.3

Путь на стенде: домашний каталог администратора, от которого запускали стенд.

```bash
ADMIN=$(logname)
sudo -u "$ADMIN" setsid "/home/$ADMIN/helpdesk-2.3/bin/helpdesk-api" >/dev/null 2>&1 < /dev/null &
sleep 1
pgrep -af 'helpdesk-2.3/bin/helpdesk-api'
```

Ожидание: одна строка с `helpdesk-2.3/bin/helpdesk-api` и владельцем `$ADMIN`.
Если `pgrep` пустой, каталог 2.3 не трогали при выкладке — смотреть `ls -l "/home/$ADMIN/helpdesk-2.3/bin"`.
Скрипт `provision.sh` этот каталог не удаляет.

## 4. Проверить, что клиентский простой не смешался с двумя копиями

```bash
pgrep -af helpdesk-api
```

Ожидание: есть только процесс 2.3. Процесса `/usr/local/bin/helpdesk-api` нет.
Две копии сразу оставлять нельзя: 2.4.1 откажется стартовать, пока жив процесс со строкой `bin/helpdesk-api`.

## 5. Что сказать дежурному

- 2.4.1 остановлена, файлы выкладки сохранены.
- 2.3 снова запущена от прежней учётной записи, уязвимость вложений на месте.
- Повторная выкладка — снова `sudo bash provision.sh` на копии, затем приёмка.
- Секреты в домашнем каталоге 2.3 не открывать и не копировать в общий каталог.
